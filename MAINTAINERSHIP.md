# Maintainership And Continuation

## Current Maintenance Boundary

The current individual maintainer has accepted active, best-effort maintenance
of the upstream project and its F-Droid distribution. Version `v0.1.0` is the
initial upstream release and the only release currently scheduled. Closing its
bounded finishing period does not declare the project unmaintained or create
an open-ended feature roadmap.

Active maintenance means monitoring the project's enabled contribution and
private vulnerability-reporting surfaces, triaging relevant reports, following
F-Droid inclusion, build, and update problems, and deciding when a correction
or release is warranted. It does not promise a support service, response time,
release schedule, acceptance of every contribution, or correction of every
reported problem.

The `oikumene-works` GitHub namespace is the project's source home; the
namespace is not presented as a legal entity, the maintainer, or a
service-level commitment.

## Proposing Stewardship

A person or group willing to maintain the project may describe a concrete plan
through the repository's enabled contribution surface. The proposal should
identify the intended scope, review and release practice, accessibility and
privacy commitments, F-Droid maintenance plan, and the people who accept those
responsibilities.

Repository administration, project naming, package identity, and F-Droid
metadata ownership transfer only through an explicit agreement with the
relevant current owner. Contributions, pull requests, issue activity, or
informal statements do not transfer those roles.

## Fork Continuation

Anyone may use, study, modify, and redistribute the source under
`GPL-3.0-or-later`. When no upstream transfer is agreed, continuation may occur
in a fork. A fork may need a new project name, Android application id, signing
identity, and distribution listing so users are not misled about continuity
with the original package.

## F-Droid

The current individual maintainer has accepted the active-maintenance
responsibility needed for the intended F-Droid submission. F-Droid acceptance
remains an external decision. If this maintenance arrangement later ends, the
project must update its public status rather than imply that an unavailable
person, the GitHub namespace, or a retired organization still maintains the
app. The project does not substitute another APK channel or promise F-Droid
acceptance.
